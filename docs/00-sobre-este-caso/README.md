# Sobre este caso

Eu sou o João Gabriel Maia da Costa, graduando em Engenharia de Software na PUC Minas e desenvolvedor full stack (JavaScript/TypeScript, Node.js, PostgreSQL, Prisma). Este repositório é o meu estudo de caso de **integração entre sistemas**, feito para mostrar como eu penso uma implantação do início ao fim: entender o problema, decidir, desenhar, construir, testar e evoluir.

## O que é verdade aqui e o que é cenário

| Item | Natureza |
|---|---|
| Código da Ponte, dos dois sistemas simples, testes, contratos, diagramas | Real. Roda localmente e os resultados registrados vêm de execuções reais. |
| "Serviços Aurora" (empresa de 25 pessoas), seus funcionários e clientes | **Fictícios**, criados para o estudo, com nomes brasileiros comuns. |
| CRM e ERP | **Sistemas simples que eu criei neste repositório** (`apps/mock-crm`, `apps/mock-erp`). Não são produtos comerciais nem representam nenhum. |
| Reuniões de discovery, aceitação e retrospectiva | **Simuladas**: o Claude interpretou o cliente e as demais pessoas. Cada registro começa com o aviso de simulação. |
| Cliente real, operação real, produção | **Não existem.** Nada foi publicado em servidor. |
| Ganhos (tempo, erros evitados) | **Hipóteses** com fórmula e entradas visíveis. Não há medição. |

Se eu tiver anotações de uma conversa real e autorizada, elas substituem a simulação e o README é ajustado.

## Por que a simulação é útil mesmo assim
A simulação me força a registrar contradições entre áreas (o comercial quer rapidez, o financeiro quer conferência), pedidos vagos e uma restrição que muda o escopo. O que ela **não** faz é validar o produto com um usuário de verdade. Está dito como limitação no README.
